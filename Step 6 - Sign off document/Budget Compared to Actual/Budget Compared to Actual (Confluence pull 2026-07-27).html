Part A. What exists today

1. What it is

Shows how actual income or spending compares to what was budgeted, per period across the fiscal year, for a chosen set of accounts. Two charts: per-period (are we on plan this period) and year-to-date cumulative (are we on plan for the year). Only the original budget is used (mid-year revisions excluded, prior doc, to confirm).

Desktop research Budget-to-actual is a core church stewardship report, reviewed monthly and taken to the board/finance committee. Favourable/unfavourable flips by account type (income over budget = good; expense under budget = good), so colour must respect the account type. Sources in Part B.

2. Where the data comes from

General Ledger: actuals from posted transactions, budget from the original budget (tables GLSummary, GLBudgetDetail, and SSUserTenantPreferenceRepository for the saved selection - prior doc, to confirm). Consolidated orgs roll up child accounts.

3b. What "Special Report Title" and "Line Description" mean

Verified live These are GL Financial Statement report concepts, not obvious to a user. Special Report Title = a saved custom financial-statement report definition (e.g. "Monthly Leadership Balance Sheet Summary", "Statement of Activities 2", "Cash Flow Report", "Trial Balance"). Line Description = one line/row on that report (e.g. "Prepaid expenses", "Land", "Buildings", "Mortgage Payable"), which groups a set of GL accounts. So Selected mode compares budget vs actual for the accounts behind a single line of a chosen report. Two live observations worth flagging: the report dropdown exposes the raw, uncurated list including obvious test/junk entries ("Column Test", "New Report", "New Report Test", "1 JF", "1BFS"); and it lets you pick balance-sheet lines (Land, Buildings) that are not meaningfully "budgeted" the way income/expense lines are. To confirm the exact GL source of these report definitions with engineering / Value Labs.

3c. How the Selected scope interacts with period / YTD (design-critical)

The Selected chain borrows a report line as an account grouping ("these accounts") and then applies the widget's own per-period and YTD budget-vs-actual to them; it does not inherit the report's own layout, columns or period logic (to confirm with engineering). That creates real mismatches the toolbar can't represent:

  • Point-in-time (balance-sheet) lines - Prepaid expenses, Land, Mortgage Payable etc. (all reachable today) are balances, not flows. "Actual vs Budget for the period" is conceptually wrong for a balance, and a YTD cumulative of a balance is meaningless (it sums month-end balances).

  • No-budget lines - balance-sheet (and many other) accounts usually have no budget, so "Budget for period" = 0 and the variance becomes "actual vs zero", a giant meaningless swing.

The period/month/YTD controls keep bucketing mechanically, but for these lines the output is nonsense. So yes - special-report data can poison the period/YTD behaviour, and today it is unguarded. The fix is a guardrail on the Selected scope, and settling the period model (see 11.8, 11.9).

Interaction check 23 Jul 2026: two side-by-side line charts confirmed and they share one Select Accounts + Refresh control, so both charts update together (Verified live 23 Jul 2026) - left = Actual/Budget for Period, right = Actual/Budget YTD, both 12-month (Jan-Dec), $ axis. 8. Competitor and analog benchmark

Desktop research Direct: Aplos, Realm/ACS, PowerChurch, ParishSOFT, QuickBooks Nonprofit, Sage Intacct - budget-to-actual by fund, variance in dollars and %, drill to the accounts behind a variance. Analog standard (IBCS / Zebra BI, Bold BI, Inforiver): grouped bar for per-period, waterfall for cumulative variance, semantic colour with an invert-for-expense option, and "don't rely on colour alone".

8b. Favourability convention. Income variance = Actual - Budget (over is good); expense variance = Budget - Actual (under is good). "Green when actual >= budget" is right for income, backwards for expense; a Selected report line (or mixed scope) has no single direction. Sources: AFP, GoCardless.

8c. SME (Ben Lane, 13 Jul, Marvin). Underutilised today but would see much more use with more flexibility. Users prefer YTD totals over individual periods (~60/40) and value switching views. A variance line showing remaining budget is highly desired. A budget-alert widget (flag when a line exceeds a % of budget, period or YTD) was requested. Custom date range must always be available; company switch global; report-style drill loved.

Part C. Designer brief

9. Target composition (what the widget should be built from)

The concrete make-up of the widget, so it can be built and demoed consistently. A floor, not a straitjacket. Each element is justified by the triage: P current production (keep what works, delete nothing used), C competitor, SME Ben Lane, DR desktop/best practice, O Oisin's demo.

Controls (header bar):

  • Account scope - a three-way control (segmented control or dropdown): All Income / All Expense / Selected. [P: exists as "Select Accounts"; income + expense to be first-class] When Selected, two cascading dropdowns appear: Report then Report line. Relabel "Special Report Title"/"Line Description" to plain "Report"/"Report line" with one line of helper text; make Report searchable/typeahead and hide empty or test reports; guard against point-in-time/no-budget lines (3c, 11.8). [DR clarity; P exposes a junk list]

  • Fiscal year selector; a specific/custom range must stay reachable. [P; SME]

  • Period vs Year-to-date - a two-item toggle switching the main chart. Frame in fiscal periods, not calendar months (11.9). [P has both; SME ~60/40 favour YTD]

  • Refresh with a visible "data as of" timestamp, separated from the refresh action. [P strength]

  • Export to Excel. [P]

  • Optional Advanced filters popover to hold the Selected report/line scope and future filters, keeping the default view simple. [DR progressive disclosure]

Views / charts (mapped to the shell's glance / detail / explore):

  • Glance (KPI): a headline variance - Actual vs Budget as a $ and %, coloured by favourability with a +/- sign, plus "% of budget used / remaining". [SME remaining-budget line; DR KPI]

  • Per-period: a grouped bar, Actual vs Budget per period. [DR IBCS/Bold BI standard first view; note: production currently renders a line chart, verified live 23 Jul 2026, not grouped bars - the bar form is a recommendation]

  • Year-to-date: a line (Actual YTD vs Budget YTD) with a remaining-budget/variance line; offer a waterfall as an alternate cumulative view. [P line, verified live 23 Jul 2026; SME remaining line; DR waterfall]

  • Data table: Actual, Budget, Variance $, Variance % per period (or per report line) - also the accessible text alternative. [DR + accessibility]

Interaction & rules:

  • Values on hover and as text in the table - never hover-only. [accessibility]

  • Favourability colour flips by account type; for a Selected report line or mixed scope show variance neutrally (sign only), since direction is ambiguous; never rely on colour alone. [DR convention; P Selected mode]

  • Drill: clicking a period or report line opens the accounts behind it in a focus overlay, in-widget. [SME drill loved]

  • Dollars are the primary unit; never label a $ figure as a %. [P bug W01 fixed]

10. States and constraints

Item

What it means

Empty (no budget)

Purposeful empty state - what the widget is, explicit zero, pointer to set up a budget (if righted). Today: silent flat-$0 charts.

No rights / no GL

Hidden or explicit no-access. To confirm @Oisin Curran @Feargal Phelan

Selected: unsupported line

A point-in-time/balance-sheet or no-budget line produces meaningless per-period/YTD variance (3c). Guard it: restrict, adapt the view, or disable with an explanation - never a silent nonsense chart.

Loading / error

Loading + retry; never blank axes that read as zero.

Original budget only

Surface that the baseline is the original budget; decide if "vs revised" is ever needed.

Period model

Canonical frame is fiscal period + YTD (+ fiscal-year selector + custom range). Fiscal period is the accounting bucket; a calendar "month" only coincides with it when the FY starts in January with 12 monthly periods. Label periods with month names where they align; never hardcode a January start (11.9).

Localisation

Currency/date must follow the org (verified defect 23 Jul 2026: $ on this widget vs GBP on Bank Balances in one org).

Company scoping

Company is global product context (SME); widget reads the active company.

Accessibility (Pathway AA)

Values as text, named controls, meaning not on colour alone.

11. Significant decisions

11.1 Two questions, two charts (per-period + YTD) is the right spine; keep both. 11.2 Favourability flips by account type; Selected/mixed scope shown neutral; pair colour with a sign/label - the correctness crux. 11.3 Original vs revised budget - surface the baseline; confirm intent. 11.4 Variance in $ (% as support); never mislabel the unit. 11.5 Grouped bar + waterfall as the chart forms; table as a peer. 11.6 Fiscal-year frame, org calendar; custom range always available. 11.7 Drill in-widget (focus overlay). 11.8 Guard the Selected scope - hide test/empty reports and relabel to plain language; and because a Selected line can be a point-in-time/balance-sheet or no-budget line for which per-period/YTD budget-vs-actual is meaningless (3c), either restrict Selected to flow (income/expense) reports/lines, or detect an unsupported line and switch the view (balance trend, no budget/variance) or disable it with an explanation - never a silent nonsense chart; also hide subtotal/heading/computed lines that do not resolve to postable accounts. 11.9 Period model - standardise on fiscal period + YTD (+ FY selector + custom range); absorb or relabel the standalone "month" control once we confirm what it drives; label periods with month names where aligned; never assume a January start. Fiscal period + YTD is the sufficient frame - a separate calendar-month option is redundant when periods = months and wrong when they differ.

14. Open questions

  • Selected-scope data model: does the widget use only the line's account set (ignoring the report's own layout/period logic)? Do the dropdowns expose non-account lines (subtotals/headings/computed)? Do balance-sheet lines carry any budget? These decide the 11.8 guardrail. @Oisin Curran

  • Period model: what does the "month" selector actually set - the reporting-through fiscal period (keep, relabel) or a separate calendar filter (drop)? Can the product have non-month or 13th/adjustment periods? (drives 11.9)

  • Should the widget restrict Selected to income/expense reports (not balance-sheet lines)? Confirm the GL source of "Special Report" definitions.

  • Favourability colour on an Expense/P&L view (Partly - to confirm 23 Jul 2026): no favourability-colour mechanism observed on the available saved view (categorical palette only) - likely a design gap; a definitive P&L/Expense test needs a reconfigured Select Accounts view (production config not mutated). Both-charts-update-together now confirmed (shared Select Accounts + Refresh control). Chart geometry settled 23 Jul 2026 (line chart, 24 point markers).

  • Data model: GLSummary/GLBudgetDetail, original-only, account type per row (for the flip). Weekly grain (F3); GL drill-through target (F4); localisation root cause (F8); entitlement/rights for the states.
