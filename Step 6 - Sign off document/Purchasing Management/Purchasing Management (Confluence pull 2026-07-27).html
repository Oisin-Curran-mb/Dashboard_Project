Part A. What exists today

1. What it is

Shows purchase-order requests filtered by where they are in the approval process - what needs my approval, what I have submitted, what is approved - alongside the encumbrance (money committed but not yet paid) those orders represent per accounting period. It is two jobs in one widget: an approval queue and a budget-commitment view.

SME Highly valued and frequently used by clients who have adopted the Purchasing module; it helps them see pending items (Marvin).

2. Where the data comes from

The Purchasing Management module. Visibility is access-controlled - administrators see all orders, other users see only orders on approval paths they are part of, and rejected orders are never shown. The encumbrance chart is calculated from the quantities and unit prices of outstanding PO lines, per period. Both filter selections are saved per user. Exact tables to confirm (prior doc).

Part B. Users and market

5. Personas

This widget centres the approver as much as the operator, because it routes purchase approvals. The bookkeeper/administrator (P1) monitors all pending orders and encumbrances (admins see everything). Approvers (department heads, pastors, finance staff on an approval path) use it to see and clear what is awaiting them. The treasurer/finance committee (P3) reads encumbrance as budget control - what is already committed against the budget.

7. Context scenarios

A. An approver opens the dashboard, sets "Awaiting my approval next", and clears the queue. B. The bookkeeper monitors all unapproved orders across paths. C. A treasurer checks committed budget before authorising more spend. D. Month-end encumbrance review - what is still committed. E. An org without the Purchasing module (or a user not on any path) - empty/absent.

8. Competitor and analog benchmark

Desktop research Two analogs. Approval queues in procure-to-pay tools (Tipalti, Bill.com bill approval, Planergy) and ERP PO workflows: an aging, actionable list where you approve/reject inline. Encumbrance / commitment reporting (Oracle, Sage Intacct, Aplos): a PO reserves budget the moment it is approved, so the honest "available" figure is budget minus actual minus encumbered - critical for churches/nonprofits protecting restricted funds and donor intent. Sources: Aplos, Grain, Tipalti, Northstar.

8b. SME. Frequently used where the module is adopted; the value is seeing pending items. Reinforces the SME's broader ask for an actionable, aging approvals/action widget (see also My Status).

Part C. Designer brief

9. Target composition (what the widget should be built from)

The concrete make-up, so it can be built and demoed consistently. A floor, not a straitjacket. Triage: P current production (keep what works, delete nothing used), C competitor, SME Ben Lane, DR desktop/best practice, O Oisin's demo.

Controls (header):

  • Status - a segmented control or dropdown: Awaiting my approval next / Awaiting my approval / Unapproved / Approved. Lead with the actionable "awaiting my approval" states. Filter values confirmed live 23 Jul 2026. [P, verified live]

  • Approval Path - dependent dropdown, defaults to All, disabled when only one path exists. [P]

  • Refresh with a "data as of" timestamp. [P pattern]

Views:

  • Glance (KPI): the actionable number - "N awaiting my approval" and total outstanding / total encumbered. [DR actionable]

  • Approval queue (table): order/req number, vendor, date, outstanding amount, with a stable core column set (adapt labels by status but keep the layout steady - live columns Requisition# | Vendor | Issued | Total) and a totals row. Show item age (how long it has waited) to support aging. [P + DR aging, verified live]

  • Encumbrance (bar chart): committed-but-unpaid per accounting period; label the concept plainly ("committed, not yet paid"); values available as text too. $ axis confirmed live 23 Jul 2026 - align currency with the org and the other widgets (£ elsewhere; resolve the per-widget currency inconsistency). [P + accessibility, verified live]

  • Data table alternative for the encumbrance figures (accessible text). [DR + a11y]

Interaction & rules:

  • Make it truly actionable: adopt the Payroll Scheduled Time Off inline approve pattern - approve/reject from an in-widget focus overlay (open the PO's Detail/Approvals inline) rather than filter-only or navigating away. Confirmed live 23 Jul 2026 that today it is a filter-only approval-workflow widget. Keep a "open full record" link for the deep case. [SME; DR; P today navigates away]

  • Clarify the filter-to-chart coupling: the encumbrance chart should make explicit whether it reflects the current status/path filter or all commitments. [prior-doc open question]

  • Respect access (admins all; others their paths; never show rejected). [P]

  • Chart values as text; name the edit/action icons; keyboard operable. [accessibility]

11. Significant design decisions

11.1 Two jobs, keep both but lead with the queue. The approval queue is the daily actionable job; the encumbrance chart is budget oversight. Keep both, but make the actionable queue primary (glance = what's awaiting me). 11.2 Make approvals actionable in-widget. Approve/reject from a focus overlay following the Payroll Scheduled Time Off inline approve pattern, not a trip to the PO module, given it is one of the few action-capable widgets and the SME wants exactly this. 11.3 Encumbrance is the commitment layer - frame it as committed-not-spent and connect it to available budget; this is the same "committed vs available" story as Budget vs Actual and Bank Balances (a cross-widget theme worth a consistent treatment). 11.4 Resolve filter-to-chart coupling (open question) so the chart's scope is unambiguous. 11.5 Stable columns, aging. Keep the table layout steady across statuses and add item age to support triage. 11.6 Accessibility parity - expose chart values as text; name the action icons.
