## 2026-09-02 - V2 spec written (unattended-policy run)

- **V2 spec created** at `v2/Deposit Accounts - API Spec.md` against the built Final, `FC_VERSION[7]` = 2.0 (Final Check tab, `WRENDER[7]` F branch, prefix `depF`), and the Step 4 doc audit-stamped 2026-08-30 (eight doc-catches-up-to-build corrections applied that day).
- **Conflict gate run: one build-vs-doc discrepancy found and NOT resolved.** The Step 4 doc (Interaction Spec and Filters sections) says Compare To drives "the overlaid line in Trend"; the built Final's Trend code (`depFTrend`) renders current-window series only, with no comparison overlay in its chart data. Per the fact-gate policy the spec funds no overlay and carries the disagreement in Still needs sign-off item 2 with both sides quoted; no winner picked. Everything else material matched: six-option Compare To with fiscal period between month and quarter, 50-per-page display pagination with full-set totals, scope-dependent 2-option breakdown, chart type-click re-scope with inert account series and Others, table-row modal preserved, Balance-descending default sort, three sizes with Jo's `large` tier dropped, 125 accounts / $106,726,837 demo set.
- **Decomposition verdict: four APIs** (scope lookup / balances summary / paginated account rows / balance series), derived from the Framework 3 triggers (trigger + lifetime gap; cardinality gap; grain gap + conditional weight). The V1 spec's open question of one endpoint versus a split is CLOSED by the framework: the bounded summary and the unbounded row list are separate, and the series is its own read.
- **Build-volume traps corrected in the contract, deviating from the mock's client-side behaviour** (the demo dataset is 125 accounts; the dossier says hundreds to thousands of depositor accounts):
  - The scope popover's account list becomes a server-side searchable lookup (API 1 `q` + `limit` + `totalAccountMatches`); the build filters all 125 client-side.
  - Table sort moves server-side (`sortBy`/`sortDir` whitelist, `accountId` tiebreaker); the build sorts the full mock set client-side.
  - Table search becomes a server param `q` spanning the full scoped set; the built Final's search narrows only the rows on the visible page (Step 4 documents that as the built behaviour). Framework hard rule applied: a paginated set means server-side search. Flagged in Still needs sign-off item 10 as a visible behaviour change. **Likely owner pushback point.**
  - `totalBalance` deliberately ignores `q` (the Total row is the scope total), matching the build's semantics where search never changes the Total row.
- **Compare To and the series window unified into one param.** The V1 spec carried separate `compareTo` and `range` params; in the built Final one control drives both the delta baseline and the trend window, so V2 has `compareTo` only, and defines `windowChangePct` (the table Trend column) as the per-account version of the same formula, making the KPI delta, table Trend column and series window agree by construction.
- **Standing ruling carried as fact (owner, 2026-08-05, from the V1 pass):** historical period-end balances are computed on demand, live per request; precompute only if performance forces it. Stated in the spec as the LIVE cache posture, without narration.
- **Standing ruling carried as fact (owner, 2026-08-05):** the out-of-widget drill-through is dropped; the in-widget re-scope and the row detail modal are the whole drill surface. Reflected in Not in scope.
- **Disputed dossier finding (dashboard grain: type-first versus account-level table) recorded with both positions and no side picked** (Still needs sign-off item 1), per the fact-gate rule. The contract funds the built Final's account-level surface; the item states what changes if the dossier direction is adopted.

## Design history relevant to the contract (from Step 4)

- The widget was renamed "Deposits On Hand" by management; the Final adopts it, while folders, files and the API key keep `deposit-accounts` pending the project-wide rename pass.
- Earlier reconciliation-based concepts (badges, Last Reconciled columns) were cut long before the Final: the data has no reconciliation concept, and the Ben Lane interview (2026-07-13) confirmed balance is primary. The V2 contract carries reconciliation only as a Not-in-scope line.
- The pre-Final concept's ~30-point daily interpolated Trend and two-option Compare To (Last Month / Last Year) are superseded by the Final's six-option scale and 8-to-12-point windows; the mock's trend series are seeded walks anchored to current balances, which is why the build is never evidence for series feasibility (Sign-off Readiness item 2 in Step 4 tracks the data-layer gate).
