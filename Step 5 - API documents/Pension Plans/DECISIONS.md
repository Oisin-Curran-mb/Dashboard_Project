- **V2 spec created** at `v2/Pension Plans - API Spec.md` against the built Final, `FC_VERSION[2]` = 2.2 (Final Check tab, `WRENDER[2]` F branch), and the Step 4 doc audit-stamped 2026-08-30. - **Decomposition verdict: three APIs** (district lookup / summary / appointee detail), derived from the Framework 3 triggers (lifetime gap; trigger + grain gap).
- **Reversal of the V1 posture, flagged for owner review.** The V1 spec (2026-07-27, revised same day to a "strict 1-to-1 contract with the existing pension-plans endpoints") kept the existing grid endpoint and had the client assemble the all-districts view and the district × plan matrix by per-district fan-out calls. The V2 spec instead defines ONE reshaped summary read (`/summary`) returning the plan rollup + `appointeeCount` + per-district cells in a single response. Reasons (Framework 2/3): the By district view is an instant client re-render in the locked design, so the matrix must be in hand from load; a fan-out's N near-simultaneous calls can straddle a write and disagree with their own merged total; partial fan-out failure has no clean render; and N is bounded only by an unconfirmed org config value. The zero-backend fan-out remains the fallback if the owner rejects the new endpoint. **This is the single most likely point of owner disagreement with the V2 spec.**
- **Chart endpoint dropped from the widget's contract.** The existing `/chart` endpoint is not called by the built Final's design (every view renders from the summary data); V1 already noted the widget does not depend on it. V2 moves it to Not in scope entirely.
- **"All Districts" option moves client-side.** Today the filters endpoint prepends an "All Districts" row server-side; the V2 contract returns real district rows only and the client renders the All option, matching the omit-the-param wire form.
- **Sign-off dossier: every finding still Unreviewed** (no `Reconciliation - Pension Plans.md` exists). Per the unattended policy this approval gate was DEFAULTED rather than halting: the spec follows the built Final and lists the dossier flags that touch the contract (data-as-of timestamp, export-scope fix, entitlement behaviour, billing/payment phase idea) in Still needs sign-off item 1 for the owner to status.
